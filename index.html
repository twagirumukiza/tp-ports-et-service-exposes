Partie 1Part 1

Cours — Comprendre la notionCourse — Understanding the concept of exposure

Avant toute manipulation pratique, cette première partie pose les bases théoriques : pourquoi un port ouvert augmente la surface d'attaque, et comment raisonner comme un auditeur face à un service exposé. Before any hands-on work, this first part establishes the theoretical foundations: why an open port increases the attack surface, and how to reason like an auditor when assessing an exposed service.

01

L'analogie de l'immeubleThe building analogy

Pour introduire la notion auprès des étudiants, l'idée centrale à transmettre est très simple : To introduce the concept to students, the central idea is simple:

Idée cléKey idea
Un port ouvert n'est pas forcément une vulnérabilité, mais chaque port exposé augmente la surface d'attaque. An open port is not necessarily a vulnerability, but every exposed port increases the attack surface.

Une bonne façon de faire comprendre ce principe est de recourir à une analogie concrète : A useful way to make this principle intuitive is to use a concrete analogy:

« Imaginez qu'un serveur soit un immeuble. Les ports sont comme des portes d'entrée, et les services sont les activités qui se déroulent derrière ces portes.

Si une porte est ouverte alors qu'on n'en a pas besoin, elle offre potentiellement un point d'entrée supplémentaire à un attaquant. » “Imagine a server as a building. Ports are like entrance doors, and services are the activities taking place behind those doors.

If a door is left open when it is not needed, it may provide an attacker with an additional entry point.”

Cette image permet de fixer un vocabulaire commun avant d'entrer dans les détails techniques : un port est un point d'accès, un service est ce qui répond derrière ce point d'accès, et une exposition inutile est une porte laissée ouverte sans raison. This analogy establishes a shared vocabulary before going into technical detail: a port is an access point, a service is the program responding through that access point, and unnecessary exposure is a door left open without a justified need.

02

Ports inutiles ouverts sur InternetUnnecessary ports exposed to the Internet

Un ordinateur peut écouter sur différents ports : le port 22 pour SSH, le port 80 pour HTTP, le port 443 pour HTTPS, etc. L'idée importante à retenir est la chaîne suivante : A machine can listen on several ports: 22 for SSH, 80 for HTTP, 443 for HTTPS, and so on. The key chain to remember is:

Port ouvertOpen port→ Service accessibleReachable service→ Interaction possiblePossible interaction

Par exemple, si un serveur web n'a aucune raison de proposer SSH directement sur Internet, laisser le port 22 accessible à tout le monde augmente inutilement son exposition. For example, if a web server has no reason to expose SSH directly to the Internet, leaving port 22 accessible to everyone unnecessarily increases its exposure.

Avec Kali, on peut illustrer cela dans un réseau de TP autorisé avec la commande suivante : With Kali, this can be demonstrated on an authorized lab network using the following command:

nmap <TARGET_IP>

Les étudiants peuvent alors observer un résultat de ce type : Students can then observe a result such as:

PORT     STATE SERVICE
22/tcp   open  ssh
80/tcp   open  http
443/tcp  open  https
Message à transmettreMessage to convey
Le but n'est pas de dire « port ouvert = faille », mais de demander : pourquoi ce port est-il ouvert ? Quel service écoute derrière ? Est-ce réellement nécessaire ? The goal is not to say “open port = vulnerability”, but to ask: Why is this port open? Which service is listening behind it? Is that service actually necessary?
03

Services non nécessaires actifsUnnecessary active services

Un service peut être installé et fonctionner alors qu'il n'est jamais réellement utilisé. Plus il y a de services actifs, plus il y a de logiciels susceptibles d'avoir une mauvaise configuration ou une vulnérabilité. A service can be installed and running even though it is never actually used. The more active services there are, the more software may introduce a misconfiguration or vulnerability.

ServeurServer
 ├── HTTP       → nécessaireneeded
 ├── HTTPS      → nécessaireneeded
 ├── SSH        → nécessaire uniquement pour l'administrationneeded for administration only
 └── ancien servicelegacy service → inutileunneeded

Sur une machine Linux de TP, on peut montrer les services en écoute avec : On a Linux lab machine, listening services can be displayed with:

ss -tuln
Distinction pédagogique importanteImportant teaching distinction
Notre première question n'est pas « comment attaquer ce service ? », mais « pourquoi ce service est-il exposé ? » — c'est cette bascule qui fait comprendre la démarche défensive plutôt qu'offensive. Our first question is not “how would I attack this service?”, but “why is this service exposed?” This shift encourages a defensive rather than offensive mindset.
04

Administration accessible depuis l'extérieurAdministrative access reachable from outside

Prenons l'exemple de SSH. Ce service permet d'administrer une machine à distance : c'est très pratique, mais si le serveur SSH est accessible depuis Internet, il devient une cible potentielle. Le même raisonnement s'applique à RDP sous Windows. Take SSH as an example. It allows remote administration of a machine, which is convenient, but if the SSH server is reachable from the Internet, it becomes a potential target. The same reasoning applies to RDP on Windows.

Administration nécessaire ?Is administrative access needed? ↓ OuiYes ↓ Doit-elle être accessible depuis Internet ?Does it need to be reachable from the Internet? ↓ Pas forcémentNot necessarily ↓ Limiter l'accèsRestrict access

Concrètement, on peut autoriser l'administration uniquement :In practice, administrative access can be limited to:

  • depuis le réseau interne ;the internal network;
  • depuis une adresse IP d'administration dédiée ;a dedicated administration IP address;
  • via un VPN ;a VPN;
  • avec une authentification forte.strong authentication.
05

Mauvaise configuration du pare-feuMisconfigured firewall

Le pare-feu constitue une sorte de filtre entre la machine et le réseau. Une configuration simplifiée pourrait être représentée ainsi : The firewall acts as a filter between the machine and the network. A simplified configuration could look like this:

Principe à retenirPrinciple to remember
N'autoriser que ce qui est nécessaire. C'est ce qu'on appelle souvent le principe de moindre privilège, appliqué ici aux communications réseau. Only allow what is necessary. This applies the principle of least privilege to network communications.
06

Démarche à adopter pendant le TPMethod to follow during the lab

Après avoir exécuté nmap, plutôt que de simplement demander aux étudiants de recopier la liste des ports, il est plus formateur de leur poser, pour chaque port découvert, la série de questions suivante : After running nmap, rather than simply asking students to copy the list of ports, it is more instructive to ask the following questions for each discovered port:

  • 1Quel service utilise ce port ?Which service uses this port?
  • 2Ce service est-il nécessaire ?Is this service necessary?
  • 3A-t-il besoin d'être accessible depuis Internet ?Does it need to be reachable from the Internet?
  • 4Si non, comment pourrait-on limiter son exposition ?If not, how could its exposure be limited?

Cette méthode transforme le TP d'un simple exercice de commandes Kali en un véritable raisonnement de sécurité. This method turns the lab from a simple Kali command exercise into an exercise in genuine security reasoning.

Message clé à faire retenirKey takeaway
Réduire la surface d'attaque, ce n'est pas fermer tous les ports : c'est exposer uniquement les services nécessaires, aux utilisateurs et réseaux qui en ont réellement besoin. Reducing the attack surface does not mean closing every port: it means exposing only the services that are necessary, to the users and networks that genuinely need them.

07

Objectif pédagogiqueLearning objective

Ce TP aborde une idée centrale en audit de sécurité réseau : le problème n'est pas simplement d'avoir des ports ouverts. Un serveur doit nécessairement exposer certains services pour fonctionner. Le risque apparaît lorsque : This lab addresses a central idea in network security auditing: the problem is not simply having open ports. A server necessarily has to expose some services to function. Risk appears when:

  • un service est exposé alors qu'il n'est pas nécessaire ;a service is exposed even though it isn't necessary;
  • un service ancien ou obsolète reste actif sans raison ;an old or obsolete service remains active without a valid reason;
  • un service d'administration (SSH, RDP...) est accessible depuis un réseau qui ne devrait pas pouvoir l'utiliser ;an administration service (SSH, RDP…) is reachable from a network that should not have access to it;
  • un pare-feu mal configuré autorise plus de trafic que nécessaire.a misconfigured firewall allows more traffic than necessary.

Port inutile ouvertUnnecessary open portCe port doit-il vraiment être accessible ?Does this port really need to be reachable?
Service inutile actifUnnecessary active serviceCe service est-il réellement nécessaire ?Is this service genuinely necessary?
Administration exposéeExposed administrationSSH / RDP doit-il être accessible depuis ce réseau ?Should SSH / RDP be reachable from this network?
Pare-feu mal configuréMisconfigured firewallLes règles autorisent-elles plus de trafic que nécessaire ?Do the rules allow more traffic than necessary?
À retenirKey point
Un port ouvert n'est pas, en soi, une vulnérabilité. C'est un fait technique qui doit être interrogé : est-il justifié, contrôlé et limité au strict nécessaire ? An open port is not, by itself, a vulnerability. It is a technical fact that must be assessed: is it justified, controlled, and limited to what is strictly necessary?

Audit de sécuritéSecurity audit
Démarche méthodique consistant à examiner un système afin d'identifier ses vulnérabilités, d'en évaluer le risque, puis de proposer et vérifier des mesures de correction.A methodical process of examining a system to identify vulnerabilities, assess their risk, and propose and verify corrective measures.
Port (réseau)Port (network)
Numéro identifiant, au sein d'une adresse IP, le point d'entrée logique utilisé par un service pour communiquer.A number that identifies the logical entry point a service uses to communicate within an IP address.
Service
Programme actif sur un serveur qui écoute sur un ou plusieurs ports et répond aux requêtes des clients.A program running on a server that listens on one or more ports and responds to client requests.
Surface d'attaqueAttack surface
Ensemble des points d'entrée par lesquels un système peut potentiellement être attaqué.The set of entry points through which a system could potentially be attacked.
Nmap
Outil de reconnaissance réseau permettant de découvrir les hôtes actifs, les ports ouverts et les services associés.A network reconnaissance tool used to discover live hosts, open ports, and associated services.
ss
Commande Linux permettant de lister les sockets réseau actifs et les ports en écoute sur une machine.A Linux command that lists active network sockets and listening ports on a machine.
systemctl
Outil de gestion des services système sous Linux.A Linux tool used to manage system services.
UFW
Interface simplifiée de gestion du pare-feu sous Ubuntu.A simplified firewall management interface for Ubuntu.
Pare-feuFirewall
Dispositif qui filtre le trafic réseau entrant et sortant selon des règles définies.A system or device that filters inbound and outbound network traffic according to defined rules.
SSH
Protocole permettant une connexion distante sécurisée et chiffrée à un serveur.A protocol that enables a secure, encrypted remote connection to a server.
RDP
